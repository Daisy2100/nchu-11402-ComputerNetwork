

## 1. Please describe the functions of data plane and control plane in each router.

每一台 router 的功能可分為 **control plane** 與 **data plane**。

**Control plane（控制平面）** 負責「決定路徑」。它執行 routing protocol（如 OSPF、RIP、BGP），與其他 router 交換 routing information，計算到各目的地的最佳路徑，並據此產生 forwarding table。它是 network-wide 的邏輯，決定封包應該怎麼走。

**Data plane（資料平面）** 負責「實際轉送封包」。當封包到達 input port 時，data plane 取出目的 IP，查詢 forwarding table，決定要送到哪個 output port / next hop，然後把封包轉送出去。它是 per-router 的本地動作，要求非常快，多由硬體或高速 forwarding engine 處理。

一句話：**control plane 決定「路怎麼走」，data plane 負責「真的把封包送出去」。**

## 2. Please describe the functions of Time to Live and Upper Layer fields in IPv4 header.

**Time to Live（TTL）**：8-bit 欄位，用來限制封包在網路中可經過的 router 數量。每經過一台 router，TTL 減 1；減到 0 時，該 router 丟棄封包並回傳 ICMP Time Exceeded 訊息。主要目的是避免封包因 routing loop 而在網路中無限循環，浪費資源。

**Upper Layer 欄位（IPv4 header 中的正式名稱為 Protocol field）**：指出 IP payload 應交給哪一個上層協定處理。此欄位只在封包抵達**目的主機**時才使用，用來把 IP 層與上層協定綁定。常見值：

| 值  | 上層協定 |
| -- | ---- |
| 6  | TCP  |
| 17 | UDP  |
| 1  | ICMP |

例如 Protocol = 6，目的主機就把 payload 交給 TCP。

## 3. What is CIDR?

**CIDR（Classless Inter-Domain Routing，無類別域間路由）** 是一種 IP 位址分配與表示方式，用「任意長度的 network prefix」取代早期的 classful addressing（Class A/B/C）。

格式為 `a.b.c.d/x`，其中 `/x` 表示前 x 個 bit 為 network prefix，其餘為 host 部分。例如 `192.168.1.0/24` 表示前 24 bits 為網路位址，剩 8 bits 分配給主機。

優點：
1. 位址分配更有彈性、更不浪費（不再受 class 邊界限制）。
2. 支援 route aggregation。
3. 縮小 Internet routing table 的規模。

---

## 4. Please describe the idea of route aggregation.

**Route aggregation（路由聚合，又稱 route summarization）** 是把多個**連續**的 subnet prefix 合併成一個較大的 prefix，使 router 只需宣告一條較短的路由。

例如以下四個 /24：

```text
200.23.16.0/24
200.23.17.0/24
200.23.18.0/24
200.23.19.0/24
```

可聚合成單一 prefix：

```text
200.23.16.0/22
```

因為 `/22` 涵蓋 `200.23.16.0`～`200.23.19.255` 的範圍。

主要好處：**減少 routing-table entries 數量，提升 Internet routing 的 scalability**。

## 5. Why must routers select the route with a more specific subnet identifier for packet forwarding to ensure correctness?

Router 查 forwarding table 時採用 **longest prefix matching（最長前綴匹配）**，即在所有符合目的 IP 的 entry 中，選擇 prefix 最長者。

原因：prefix 越長代表越 specific，也就是越精確地指向目的網路。若選了較不 specific 的路由，封包可能被送往錯誤方向。

例：forwarding table 中有

| Prefix         | Next hop |
| -------------- | -------- |
| 200.23.16.0/20 | ISP A    |
| 200.23.18.0/23 | ISP B    |

目的地 `200.23.18.7` 同時符合 `200.23.16.0/20` 與 `200.23.18.0/23`，但 `/23` 比 `/20` 更 specific，故 router 必須選 `200.23.18.0/23 → ISP B`。

選最長前綴可保證封包送往最精確、正確的目的網路，避免 forwarding 錯誤。

## 6. Please describe the operations of link-state routing algorithm.

核心概念：**每台 router 都掌握整個網路拓樸，再各自計算最短路徑。**

運作流程：
1. 每台 router 量測自己到各鄰居的 link cost。
2. 每台 router 產生 link-state packet（LSP），內容含：自己的 ID、鄰居清單、到各鄰居的 link cost。
3. 把 LSP 透過 **flooding** 散播給網路中所有 router。
4. 所有 router 收到完整資訊後，各自建立**相同**的 network topology graph。
5. 每台 router 以 **Dijkstra algorithm** 計算到所有目的地的 shortest path。
6. 依結果產生 forwarding table。

代表協定：**OSPF**。

## 7. Please use an example to explain why link-state routing algorithm would cause route oscillation.

當 **link cost 隨流量負載動態變化**，且所有 router 幾乎同時重算路由時，可能發生 route oscillation。

假設從 S 到 D 有兩條路徑：

```text
Path 1: S → A → D
Path 2: S → B → D
```

**第 1 輪**：Path 1 成本較低，全部流量走 Path 1。

```text
Path 1 cost = 5,  Path 2 cost = 8
```

**第 2 輪**：大量流量壅塞 Path 1，使其 cost 上升；router 重算後發現 Path 2 較便宜，流量全改走 Path 2。

```text
Path 1 cost = 12, Path 2 cost = 8   →  流量移到 Path 2
```

**第 3 輪**：流量離開後 Path 1 cost 回落，Path 2 反而壅塞、cost 上升；router 又把流量切回 Path 1。

```text
Path 1 cost = 5,  Path 2 cost = 13  →  流量切回 Path 1
```

結果流量在兩條路徑間來回擺盪：

```text
Path 1 → Path 2 → Path 1 → Path 2 → ...
```

這就是 route oscillation。根因是 **cost 依賴流量負載 + 全網同步重算**，造成整體流量在不同路徑間反覆震盪。

## 8. Please describe the operations of distance-vector routing algorithm.

核心概念：**每台 router 不需知道整個拓樸，只需知道「透過哪個鄰居到目的地成本最低」。**

每台 router 維護一張 distance vector，記錄到所有目的地的目前估計距離。運作流程：
1. 初始化自己的 distance table。
2. 只與**直接相鄰**的 router 交換 distance vector。
3. 收到鄰居的 DV 後，用 **Bellman-Ford equation** 更新自己的最短距離估計。
4. 若自己的估計有改變，就把新的 DV 傳給鄰居。
5. 重複直到全部 router 收斂。

Bellman-Ford equation：

```text
D_x(y) = min_v { c(x,v) + D_v(y) }
```

* `D_x(y)`：x 到目的地 y 的最短距離估計
* `v`：x 的鄰居
* `c(x,v)`：x 到鄰居 v 的 link cost
* `D_v(y)`：鄰居 v 到 y 的距離估計

此演算法是 **iterative、asynchronous、distributed**。代表協定：**RIP**。

## 9. Please describe the problem of count-to-infinity for distance-vector routing algorithm.

**Count-to-infinity** 是 distance-vector 在 link cost 上升或 link failure 後常見的問題；本質是「好消息傳得快、壞消息傳得慢」。

假設拓樸（各 link cost = 1）：

```text
A --- B --- C --- N
```

原本：

| Router | 到 N 的 cost | Next hop |
| ------ | ---------: | -------- |
| C      |          1 | direct   |
| B      |          2 | C        |
| A      |          3 | B        |

當 **C 到 N 的 link 壞掉**，C 知道自己到不了 N，但 B 還以為能透過 C 到 N（cost 2），A 還以為能透過 B 到 N（cost 3）。

此時 B 從 A 聽到「A 到 N，cost = 3」，誤以為可透過 A 到 N（cost = 1 + 3 = 4）—— 但 A 的這條路其實是繞回 B 的。於是 B 與 A 互相誤導，形成 loop：

```text
B → A → B → A → ...
```

兩者的 cost 每輪緩慢遞增：

```text
3 → 4 → 5 → 6 → ...
```

一直「數到無限大」，直到達到協定定義的 infinity 值（RIP 中為 16）才停止。整個過程收斂極慢，這就是 count-to-infinity。

---

## 10. Please show how poisoned reverse solves the problem of count-to-infinity.

**Poisoned reverse** 概念：若 router X 是**透過鄰居 Y** 到達某目的地，則 X 在向 Y 宣告自己的 distance vector 時，會故意宣告自己到該目的地的距離為 **infinity**，讓 Y 不會誤以為能繞回 X。

例：

```text
A --- B --- C --- N
```

A 透過 B 到 N（A → B → C → N），所以 A 對 B 宣告「A 到 N = infinity」：

| Router | 真正使用的 route | 對 next hop 的宣告           |
| ------ | ----------- | ------------------------ |
| A      | 透過 B 到 N    | 對 B 宣告 A 到 N = infinity |
| B      | 透過 C 到 N    | 對 C 宣告 B 到 N = infinity |

如此一來，當 C–N 斷線、C 設成 infinity 時，B **不會**再從 A 收到「A 能到 N（cost 3）」的假象（因為 A 對 B 報的是 infinity），於是 B 不會繞回 A，避免了兩節點互相誤認的 loop。

注意：poisoned reverse 能解決**兩個 router 之間**的 loop，但對**三個以上 router 形成的環路**不一定有效。

## 11. Please compare link-state and distance-vector algorithms in terms of message complexity, convergence speed and robustness.

| 比較項目 | Link-state (LS) | Distance-vector (DV) |
| ------- | --------------- | -------------------- |
| **Message complexity** | 較高。每台 router 需把 link-state 資訊 **flood 給全網**，共需 O(N·E) 等級的訊息量（N 個節點、E 條 link）。 | 較低。每次只與**直接鄰居**交換 DV；但收斂時間不定，壞消息可能在網路中反覆傳播。 |
| **Convergence speed** | 通常較快；演算法本身為 O(N²)，但若 link cost 依流量變動可能 oscillation。 | 通常較慢；可能發生 routing loop 與 count-to-infinity，收斂時間變動大。 |
| **Robustness** | 較好。router 只會對「自己的 link」宣告（可能錯誤的）cost，且各 router 各自獨立計算路徑，錯誤影響較侷限。 | 較差。一個節點可能對「到所有目的地」宣告錯誤的路徑成本，且錯誤會沿網路傳播擴散。 |

簡言之：LS 收斂快、資訊完整、較可靠，但訊息成本高；DV 訊息成本低、實作簡單，但收斂較慢且易有 loop。

## 12. Please describe the concept and benefits of hierarchical OSPF.

**概念**：把一個大型 AS 切成多個 **area**，採兩層階層：

```text
Backbone Area (Area 0)
Non-backbone Areas (Area 1, Area 2, ...)
```

每個 area 內的 router 只需知道**該 area 內**的完整拓樸；不同 area 透過 **Area Border Router（ABR）** 連到 backbone area 互通。整個 AS 與外部則由 boundary router 連接。

**好處**：
1. 減少每台 router 需儲存的 topology information。
2. 限縮 link-state flooding 的範圍（只在 area 內）。
3. 減小 routing table 大小。
4. 提升大型網路的 scalability。
5. 將拓樸變動限制在單一 area 內，不影響整個 AS（例如 Area 1 某條 link cost 改變，通常只在 Area 1 內 flood）。

## 13. Please explain how Internet uses intra-AS and inter-AS routing to achieve scalable routing.

Internet 由許多 **Autonomous System（AS）** 組成（ISP、公司、學校等），routing 分兩層：

**Intra-AS routing**：AS **內部**的 routing，使用如 OSPF、IS-IS、RIP，負責在同一 AS 內選擇路徑。

**Inter-AS routing**：AS **之間**的 routing，使用 **BGP**，負責不同 AS 間的可達性與政策控制。

此分層設計達成 scalable routing 的原因：
1. 每個 AS 可**自行決定**內部使用哪種 routing protocol（管理自主）。
2. 不需讓所有 router 都知道全球完整拓樸（用 prefix 聚合）。
3. BGP 支援基於商業關係（customer/provider/peer）的政策。
4. routing table 與 routing update 的規模可被有效控制。

因此 intra-AS 處理 AS 內部細節、inter-AS 處理 AS 之間的連接與政策，整體達成可擴展的路由。

## 14. Please describe the functions of eBGP and iBGP sessions.

**eBGP（External BGP）**：建立於**不同 AS** 的 router 之間。

```text
AS1 router  ← eBGP →  AS2 router
```

功能：在不同 AS 間交換 prefix reachability information；宣告自己或自己 customer 可達的 prefixes；傳遞 AS-PATH、NEXT-HOP 等 BGP attributes；支援 AS 間的 routing policy。

**iBGP（Internal BGP）**：建立於**同一 AS 內部**的 router 之間。

```text
AS1 internal router  ← iBGP →  AS1 border router
```

功能：把從 eBGP 學到的外部路由傳遞給 AS 內所有 router；讓 AS 內各 router 都知道如何到達外部 prefixes；維持 AS 內 BGP policy 決策的一致性。

```text
eBGP：AS 與 AS 之間交換路由
iBGP：AS 內部傳遞 BGP 學到的外部路由
```

## 15. Please describe the generation of forwarding-table entries in a router with BGP and OSPF.

在一個 AS 內，**BGP 決定「從哪個 border router 離開 AS」，OSPF 決定「AS 內部如何走到那個 border router」**，兩者配合產生 forwarding-table entry。

流程：
1. Border router 透過 **eBGP** 從其他 AS 學到外部 prefix。
2. Border router 透過 **iBGP** 把外部 prefix 傳給 AS 內其他 router。
3. Router 執行 **BGP route selection**，對某 external prefix 選出最佳 BGP route。
4. 該 route 指出 BGP **next hop**（通常是某個 border router）。
5. Router 用 **OSPF** 計算自己到該 BGP next hop 的 AS 內最短路徑，得到「下一跳介面」。
6. 把結果寫入 forwarding table。

例：

```text
目的 prefix:     138.16.0.0/16
BGP 選擇出口:    Border Router R3
OSPF 計算:       本 router 到 R3 須先送給 R2
Forwarding entry: 138.16.0.0/16 → next hop R2
```

所以 forwarding table 是 **BGP（決定外部出口）＋ OSPF（決定內部路徑）** 共同產生。

## 16. Please describe how hot potato routing works.

**Hot potato routing** 是一種 BGP 出口選擇策略：當 AS 有多個出口都能到達同一 external prefix 時，router 選擇 **intra-AS（IGP / OSPF）cost 最低、離自己最近**的出口，盡快把封包丟出自己的 AS。

例：AS1 內部 router R0，兩個出口 R1、R2 都能到 prefix X：

| 出口 router | OSPF cost |
| --------- | --------: |
| R1        |         5 |
| R2        |        20 |

即使 R2 之後的 inter-AS path 可能更短，R0 仍選擇 R1，因為 R1 的 AS 內部成本最低。

目的不是讓 end-to-end path 最短，而是**降低自己 AS 內部承擔的傳輸成本**。

```text
Hot potato routing = choose the exit with the least intra-AS cost
```

## 17. Please use examples to examine the operations of policy for BGP.

BGP 是 **policy-based routing**，不只看 shortest path，還依商業關係與政策選路。

**例一：customer route 優先於 peer route**
AS A 對同一 prefix P 收到兩條路：

| Route   | 關係          | AS-PATH   |
| ------- | ----------- | --------- |
| Route 1 | 來自 customer | A → C → P |
| Route 2 | 來自 peer     | A → D → P |

即使 Route 2 的 AS-PATH 較短，A 仍可能選 Route 1，因為 customer 會付錢，商業利益較高。常見偏好順序：

```text
Customer route > Peer route > Provider route
```

**例二：不替 provider / peer 做 transit（export policy）**
一般的宣告政策：

```text
從 customer 學到的 route：宣告給 provider、peer、customer（皆可）
從 peer    學到的 route：通常只宣告給 customer
從 provider 學到的 route：通常只宣告給 customer
```

例如 A 從 provider P 學到的 route 不會宣告給 peer X，否則 A 會變成 P 與 X 之間的免費 transit。

**例三：用 AS-PATH 避免 routing loop**
若 AS1 收到一條 route：

```text
Prefix X,  AS-PATH: AS3 AS2 AS1
```

AS-PATH 中已含 AS1，代表接受它會形成 loop，故 AS1 **拒絕**這條 route。

**例四：用 local preference 控制出口**
某公司同時連兩個 ISP：

| Route  | Local Preference |
| ------ | ---------------: |
| 經 ISP1 |              200 |
| 經 ISP2 |              100 |

BGP 優先選 local preference 較高者，故平常流量走 ISP1（較便宜），只有 ISP1 不可用時才改走 ISP2（備援）。

**小結**：BGP policy 可控制
1. 哪些 route 可被接受（import policy）；
2. 哪些 route 可被宣告出去（export policy）；
3. 哪條 route 優先使用（local preference 等）；
4. 如何依商業關係、成本、安全與備援需求選路。

因此 BGP 是 policy-based routing，而非單純的 shortest-path routing。
